feat(appkit): add NSTouch and NSViewCornerConfiguration

A macOS app booted under the dyld shared cache reports the AppKit class
and metaclass exports of NSTouch, NSViewCornerConfiguration as kept: the Cocotron stand-in has none,
so cache code keeps pointing at cache classes that objc never registered.
Each is documented by Apple, so the class is added here (class and metaclass
both exported).

Rung 3 (public documentation), one page per class:
- https://developer.apple.com/documentation/appkit/nstouch
- https://developer.apple.com/documentation/appkit/nstouch/touchtype
- https://developer.apple.com/documentation/appkit/nstouch/touchtypemask
- https://developer.apple.com/documentation/appkit/nstouch/phase-swift.struct
- https://developer.apple.com/documentation/appkit/nsviewcornerconfiguration

Behaviour:
- NSTouch: NSObject, NSCopying; the seven read-only properties and the two location methods, plus NSTouchType, NSTouchTypeMask, NSTouchPhase and NSTouchTypeMaskFromType.
- NSViewCornerConfiguration: NSObject, NSCopying; the capsule class property and the factories the class page lists. NSViewCornerRadius is only forward declared.

GUESS (rung 6, nothing above answers it; confirm on a real Mac):
- The NSTouchType, NSTouchTypeMask and NSTouchPhase values (the pages give names only): one bit per constant, Touching the union of Began, Moved and Stationary, Any all bits.
- locationInView: and previousLocationInView: return the origin; the page does not say how a normalized position maps into a view.
- Every NSViewCornerConfiguration factory returns an empty instance and keeps none of its arguments; an unimplemented instance message is logged once (NS_STUB_FORWARDING).

Verified in a plain arm64 guest: the new test checks class, metaclass,
superclass, property types and the documented defaults and passes; the same
test fails against the #530 base, where the symbols are absent.
